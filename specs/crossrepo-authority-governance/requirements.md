# ORG-AUTH requirements

| ID | Requirement | Verification |
|---|---|---|
| `ORG-AUTH-R001` | **Duplicate-authority register entry contract.** The organization hub publishes a machine-readable authority-register.json with a version and an entries array; each entry records a stable ID, capability name, authority_repo, consumer_repos, owner_spec_url, consumer_spec_urls, decision_state, and receipts, with repository names and URLs restricted to public GitHub resources. Caller chain: the `Hub script tests` step (`.github/workflows/tests.yml:24`) runs `python -m pytest -q tests`, which runs `tests/test_authority_register.py` (planned), which calls `validate_register` in `scripts/authority_register.py` (planned) on `specs/crossrepo-authority-governance/authority-register.json`. Shape: new `scripts/authority_register.py` that checks `schema_version` (the key the register file already holds) and the `entries` array, with `validate_register(doc: dict) -> list[str]` returning one finding per violation, and `main()` shaped like `main` in `scripts/check_front_door.py:108` (`--root` argument, exit 1 on a finding); the enumerations of decision states and receipt kinds are module constants the test imports. No second JSON loader: reuse `json.loads` on the file text. | A contract check validates the register's JSON schema and confirms every decision_state value and receipt kind against the documented enumeration. Test: Planned `tests/test_authority_register.py::test_register_schema_rejects_missing_fields_and_unknown_states`. |
| `ORG-AUTH-R002` | **Single authority consolidation per capability.** Each capability the register tracks resolves to exactly one authority_repo once its entry reaches DECIDED, and a CLOSED entry leaves no competing authority or duplicate implementation across the public repositories it names. Caller chain: the `Hub script tests` step (`.github/workflows/tests.yml:24`) runs `python -m pytest -q tests`, which runs `tests/test_authority_register.py` (planned), which calls `validate_register` in `scripts/authority_register.py` (planned) on `specs/crossrepo-authority-governance/authority-register.json`. Shape: one function `check_single_authority(entries) -> list[str]` in `scripts/authority_register.py` (planned), grouping entries by capability name and failing a group whose DECIDED or later entries name different `authority_repo` values, and a CLOSED entry that lists a competing authority. | A register audit confirms no two entries name the same capability with different authority_repo values once either reaches DECIDED. Test: Planned `tests/test_authority_register.py::test_one_authority_per_capability_once_decided`. |
| `ORG-AUTH-R003` | **Authority register contribution and ownership rules.** Owner repositories publish their own API, data, migration, and failure contracts for a tracked capability, consumer repositories publish integration and negative tests against them, and a change to an existing capability reuses that owner's established wiring and component boundaries rather than adding a second store, writer, policy engine, or generated client. Caller chain: the `Hub script tests` step (`.github/workflows/tests.yml:24`) runs `python -m pytest -q tests`, which runs `tests/test_authority_register.py` (planned), which calls `validate_register` in `scripts/authority_register.py` (planned) on `specs/crossrepo-authority-governance/authority-register.json`. Shape: `check_linked_specs(entries) -> list[str]` in `scripts/authority_register.py` (planned): a DECIDED entry must carry one `owner_spec_url` and at least one `consumer_spec_urls` item; the owner and consumer checks themselves stay in the owner and consumer repositories. | Each owner and consumer repository's own CCCC, jscpd, Dupehound, and KISS checks gate the implementing change. Test: Planned `tests/test_authority_register.py::test_decided_entry_links_owner_and_consumer_specs`. |
| `ORG-AUTH-R004` | **Register scope excludes deployment-specific detail.** The register records public architecture decisions only; environment-specific deployment configuration is never required to build or test a public contribution, and a CLOSED entry reflects removal of the superseded implementation rather than its retention alongside the new one. Caller chain: the `Hub script tests` step (`.github/workflows/tests.yml:24`) runs `python -m pytest -q tests`, which runs `tests/test_authority_register.py` (planned), which calls `validate_register` in `scripts/authority_register.py` (planned) on `specs/crossrepo-authority-governance/authority-register.json`. Shape: `check_public_urls(entries) -> list[str]` in `scripts/authority_register.py` (planned): every repository name and URL must be a public `github.com/Knuckles-Team` resource, and a CLOSED entry must hold an `implementation` receipt whose commit is a full 40-character SHA. | A contribution review confirms the baseline build and test instructions run from the public repository alone, with no reference to non-public deployment configuration. Test: Planned `tests/test_authority_register.py::test_register_rejects_non_public_urls_and_short_shas`. |
| `ORG-AUTH-R005` | **Unresolved-owner decisions stay visible as PROPOSED.** A cross-repository obligation that has no assigned authority_repo yet is recorded as a PROPOSED register entry carrying its capability name and affected consumer repositories, rather than being omitted from the register until an owner is found. Caller chain: the `Hub script tests` step (`.github/workflows/tests.yml:24`) runs `python -m pytest -q tests`, which runs `tests/test_authority_register.py` (planned), which calls `validate_register` in `scripts/authority_register.py` (planned) on `specs/crossrepo-authority-governance/authority-register.json`. Shape: `validate_register` (planned) accepts a PROPOSED entry with an empty `authority_repo` when it names a capability and at least one consumer repository; the register summary in `render` (`scripts/public_spec_report.py:364`) must list such an entry as unresolved and never as accepted. | A register audit confirms every known cross-repository obligation appears as an entry in at least the PROPOSED decision_state, with none silently absent. Test: Planned `tests/test_authority_register.py::test_proposed_entry_without_owner_is_accepted_and_shown_unresolved`. |
