# ORG-AUTH-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `ORG-AUTH-R001` | **Duplicate-authority register entry contract.** The organization hub publishes a machine-readable authority-register.json with a version and an entries array; each entry records a stable ID, capability name, authority_repo, consumer_repos, owner_spec_url, consumer_spec_urls, decision_state, and receipts, with repository names and URLs restricted to public GitHub resources. | A contract check validates the register's JSON schema and confirms every decision_state value and receipt kind against the documented enumeration. |
| `ORG-AUTH-R002` | **Single authority consolidation per capability.** Each capability the register tracks resolves to exactly one authority_repo once its entry reaches DECIDED, and a CLOSED entry leaves no competing authority or duplicate implementation across the public repositories it names. | A register audit confirms no two entries name the same capability with different authority_repo values once either reaches DECIDED. |
| `ORG-AUTH-R003` | **Authority register contribution and ownership rules.** Owner repositories publish their own API, data, migration, and failure contracts for a tracked capability, consumer repositories publish integration and negative tests against them, and a change to an existing capability reuses that owner's established wiring and component boundaries rather than adding a second store, writer, policy engine, or generated client. | Each owner and consumer repository's own CCCC, jscpd, Dupehound, and KISS checks gate the implementing change. |
| `ORG-AUTH-R004` | **Register scope excludes deployment-specific detail.** The register records public architecture decisions only; environment-specific deployment configuration is never required to build or test a public contribution, and a CLOSED entry reflects removal of the superseded implementation rather than its retention alongside the new one. | A contribution review confirms the baseline build and test instructions run from the public repository alone, with no reference to non-public deployment configuration. |
| `ORG-AUTH-R005` | **Unresolved-owner decisions stay visible as PROPOSED.** A cross-repository obligation that has no assigned authority_repo yet is recorded as a PROPOSED register entry carrying its capability name and affected consumer repositories, rather than being omitted from the register until an owner is found. | A register audit confirms every known cross-repository obligation appears as an entry in at least the PROPOSED decision_state, with none silently absent. |
