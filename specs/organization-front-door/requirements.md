# ORG-FRONT-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `ORG-FRONT-R001` | **Organization front door describes the five-repository flow.** The organization-level README presents the ecosystem's five public repositories in present tense, with an accurate description of how the web UI connects to the graph engine service, and only links that resolve successfully. | An automated link check confirms every linked URL in the front door returns HTTP 200, and a rendering check confirms the page displays correctly on GitHub. |
| `ORG-FRONT-R002` | **The organisation README links every repository's spec-delivery page.** The organisation README must link each repository page at `https://knuckles-team.github.io/<repo>/spec-delivery/`. Children implement `PIPE-PAGES-R014.5` (organisation, then repository, then spec). | Children R002.1 to R002.4 pass. |
| `ORG-FRONT-R002.1` | **One list names the repositories with a page.** `SPEC_DELIVERY_PAGES` in `scripts/public_spec_report.py` must list only repositories whose page returns HTTP 200. | `tests/test_front_door.py::test_readme_spec_delivery_links_match_the_single_list` |
| `ORG-FRONT-R002.2` | **A generated block renders the section.** `scripts/spec_delivery_links.py --write` must render the block between the spec-delivery markers in `profile/README.md`. | Same test; the block equals `render()`. |
| `ORG-FRONT-R002.3` | **The README links match the list.** Every spec-delivery link in `profile/README.md` must equal the list and use the exact page form. | Same test. |
| `ORG-FRONT-R002.4` | **Each repository block links its page.** Each per-repository block in the README should carry a "Spec delivery" link when its page exists. | Same test. |
| `ORG-FRONT-R003` | **The organization site serves the canonical architecture explorer.** The organization Pages site must publish the Arbora Architecture Explorer at `https://knuckles-team.github.io/.github/architecture/`, built by the pipelines generator in github mode without a vendored copy, and the front-door pages must send visitors there. Children R003.1 to R003.3. | Children R003.1 to R003.3 pass. |
| `ORG-FRONT-R003.1` | **The site workflow builds the explorer and keeps it current.** `.github/workflows/spec-status-pages.yml` must check out `scripts/architecture_explorer` from pipelines `main`, build `site/architecture/index.html` in github mode, run every 30 minutes and on `repository_dispatch: specs-changed`, and keep building `site/spec-status.html`. | `tests/test_architecture_explorer_site.py::test_site_workflow_builds_the_explorer_on_a_schedule` |
| `ORG-FRONT-R003.2` | **The profile sends visitors to the explorer at the top level.** Every specification-status link in `profile/README.md` must point to the bare explorer URL with no `#<node>` anchor, and its prose must say that the explorer shows every spec row with its status and that `SPECIFIED` rows are open work. The runtime diagram in `profile/README.md` and `README.md` must link the explorer, with an "Explore the live architecture" text link. | `tests/test_front_door.py::test_front_door_links_the_explorer_at_the_top_level` |
| `ORG-FRONT-R003.3` | **The link evidence covers the explorer.** `evidence/links.json` must record a passing HTTP 200 check for the explorer URL against the current `profile/README.md`. | `python scripts/check_front_door.py` passes and `evidence/links.json` lists the explorer URL as passed. |
| `ORG-FRONT-R004` | **The status report reads schema version 2 natively.** `scripts/public_spec_report.py` and `scripts/requirement_progress.py` must accept the generated status vocabulary SPECIFIED, LANDED, VERIFIED and RETIRED. LANDED needs at least one `landed_in` commit reachable from the owner's default branch; VERIFIED also needs a non-empty `verified_by`; RETIRED is closed and leaves the percentage. A claim whose evidence fails is shown as UNKNOWN with the reason. Version 1 manifests keep working. | `tests/test_requirement_progress.py::test_v2_verified_and_landed_count_as_delivered`, `::test_v2_sha_off_main_or_missing_demotes_with_a_reason`, `::test_v2_verified_needs_tests_and_unknown_states_are_rejected`, `::test_v2_retired_is_closed_and_leaves_the_denominator`; `tests/test_public_spec_report.py::test_v2_committed_specs_counts_verified_and_demotes_off_main` |
| `ORG-FRONT-R005` | **The status page shows the state breakdown.** The generated page must show a SPECIFIED, LANDED, VERIFIED and RETIRED breakdown with percent delivered for each repository and each spec, and its legend must explain the version 2 states and the demotion rule. | `tests/test_public_spec_report.py::test_v2_committed_specs_counts_verified_and_demotes_off_main` (rendered page) |
| `ORG-FRONT-R006` | **A root AGENTS.md is the agent front door.** `AGENTS.md` at the repository root must state what the organization is, the core repositories and their ownership boundary, how to pick work, a six-step contribution path, a smallest-contribution fast path, and a cheat sheet of statuses, trailers and the ID pattern, and must link the ownership standard, the spec standard, the spec status report and the shared skills. | `tests/test_front_door.py::test_agents_md_is_the_agent_front_door` |
| `ORG-FRONT-R007` | **Agent entry points are wired in.** `CLAUDE.md` must contain only `@AGENTS.md`, and `profile/README.md` and `CONTRIBUTING.md` must open with a short pointer to `AGENTS.md`. | `tests/test_front_door.py::test_agent_entry_points_point_at_agents_md` |
| `ORG-FRONT-R008` | **A plain-text pointer serves agents.** `site/llms.txt` is published at the site root and names the front door, the architecture explorer, the contribution guide, the skills directory, the spec-details file pattern and the five-step contribution path. | `tests/test_front_door.py::test_site_llms_txt_points_agents_at_the_front_door_and_contribution_path` |
